## 2. Correção de Performance do Layout (Dashboard)

### Causa

O `(dashboard)/layout.tsx` re-executa `getServerSession()` a cada troca de rota, fazendo round-trip ao banco em cada navegação.

### Solução

**Sessão uma vez:** O layout (Server Component) busca a sessão e passa via props para `<DashboardShell>` (Client Component). Páginas filhas consomem `useSession()` do NextAuth (cache interno do client) — sem nova query ao banco.

**Socket.IO singleton:** `src/lib/socket-client.ts` exporta instância única (`let socket = null; if (!socket) socket = io(...)`). O `join:tenant` é emitido uma única vez na montagem do `DashboardShell`.

**AlertsProvider no layout:** Client Component no `DashboardShell` faz um único fetch de `/api/alertas/count` na montagem e atualiza apenas via `socket.on('alerta:novo')`. Nenhuma rota filha refaz essa query — consome o contexto do provider.

**React Query defaults:** `QueryClientProvider` com `defaultOptions: { queries: { staleTime: 60_000 } }` — evita refetch agressivo em cada montagem de página.

## 3. Módulo 11 — Sistema de Alertas Inteligentes

### Schema Prisma

```prisma
enum TipoAlerta  { ESTOQUE FINANCEIRO OPERACIONAL SISTEMA }
enum Severidade  { CRITICA ALTA MEDIA BAIXA INFO }
enum StatusAlerta { NAO_LIDO LIDO RESOLVIDO IGNORADO }

model Alert {
  id          String      @id @default(cuid())
  tenantId    String
  tipo        TipoAlerta
  severidade  Severidade
  titulo      String
  descricao   String
  status      StatusAlerta @default(NAO_LIDO)
  insumoId    String?
  produtoId   String?
  metadata    Json
  criadoEm   DateTime    @default(now())
  lidoEm     DateTime?
  resolvidoEm DateTime?
  tenant      Tenant      @relation(fields: [tenantId], references: [id])
  @@index([tenantId, status])
  @@index([tenantId, tipo, insumoId])
}

model AlertConfig {
  id                    String   @id @default(cuid())
  tenantId              String
  tipoAlerta            String
  ativo                 Boolean  @default(true)
  threshold             Json
  canais                Json     // { sistema: true, email: string[], whatsapp: string[] }
  horarioSilencioInicio String?
  horarioSilencioFim    String?
  @@unique([tenantId, tipoAlerta])
  @@index([tenantId])
}
```

### Jobs BullMQ

Registrados no `server.ts` após o Socket.IO:

| Worker | Arquivo | Trigger |
|---|---|---|
| EstoqueAlertWorker | `src/jobs/alerts/estoque.job.ts` | `{ every: ALERT_JOB_INTERVAL_MS }` |
| FinanceiroAlertWorker | `src/jobs/alerts/financeiro.job.ts` | Cron `'0 23 * * *'` |
| OperacionalAlertWorker | `src/jobs/alerts/operacional.job.ts` | `{ every: KDS_ALERT_JOB_INTERVAL_MS }`, com guard de horário de funcionamento |

**Padrão interno de cada job:**
1. Buscar tenants ativos
2. Para cada tenant, verificar `AlertConfig` — pular se `ativo: false`
3. Checar horário de silêncio antes de criar
4. Anti-spam: query por `tenantId + tipo + insumoId + status IN [NAO_LIDO, LIDO]` — não criar se existir
5. `prisma.alert.create`
6. `io.to(tenantId).emit('alerta:novo', alert)`

**Job 1 — Estoque** (6 verificações por tenant):
- `currentQty = 0` → CRITICA, "zerou o estoque", ação "Lançar entrada"
- `currentQty < minimumQty` → ALTA, "abaixo do mínimo (X unidades)", ação "Lançar entrada"
- `currentQty < pontoReposicao` → MEDIA, "chegando ao ponto de reposição", ação "Planejar compra"
- `dataValidade <= now() + 7d` → ALTA, "vence em X dias", ação "Ver insumo"
- `dataValidade < now()` → CRITICA, "está vencido — remover do estoque", ação "Lançar baixa"
- Divergência pós-inventário > 10% → ALTA, listar maiores divergências

**Job 2 — Financeiro** (5 verificações por tenant):
- CMV% do dia > 38% → ALTA, "CMV elevado hoje: X%"
- CMV elevado por 3 dias consecutivos → severidade aumentada + email para ADMIN
- Vendas do dia < 70% da média dos últimos 7 dias → ALTA, "Vendas X% abaixo da média"
- Meta diária atingida → INFO, "Meta do dia atingida! R$ X vendidos"
- Ticket médio dos últimos 3 dias < média 30 dias anteriores em > 15% → MEDIA

**Job 3 — Operacional** (3 verificações por tenant, respeitando horário de funcionamento):
- Pedidos com status ABERTO sem movimentação > 10min → ALTA, "X pedidos parados na fila"
- Pedido EM_PREPARO há > 2× tempo médio histórico do produto → ALTA
- Mais de 3 cancelamentos em 1 hora → ALTA

### API Routes

| Método | Rota | Detalhe |
|---|---|---|
| GET | `/api/alertas` | `?tenantId&tipo&status&page&limit` — paginado |
| PATCH | `/api/alertas/[id]` | `{ status: 'LIDO' \| 'RESOLVIDO' \| 'IGNORADO' }` |
| GET | `/api/alertas/count` | `?tenantId` → `{ count: number }` |
| GET | `/api/alert-configs` | `?tenantId` |
| PATCH | `/api/alert-configs/[id]` | Atualiza threshold, canais, horário silêncio |

### UI

**Header** — `AlertsBadge`: fetch único na montagem + update via `socket.on('alerta:novo')`.

**Painel lateral** — `AlertsDrawer` no `DashboardShell`: últimos 5 alertas, ícone+cor por tipo, botão de ação contextual.

**Página `/alertas`** — tabela com filtros (tipo, status, período, busca texto), paginação server-side. Ícone+cor por tipo, dropdown de status inline, botão de ação.

**Página `/configuracoes/alertas`** (ADMIN) — card por tipo: toggle ativo, threshold editável, email multi-select, WhatsApp placeholder "Fase 3", inputs de horário de silêncio. PATCH para `/api/alert-configs/[id]`.

### Fluxo de autenticação

```
Abrir app
  └─ AsyncStorage tem 'restroOS:slug'?
       ├─ Não → campo de slug → GET /api/tenants/[slug]/verify → salvar → lista
       └─ Sim → lista de cozinheiros

                 └─ Digitar PIN → POST /api/auth/pin → JWT

```

### Tela principal KDS

- `expo-screen-orientation.lockAsync(LANDSCAPE)` + `expo-keep-awake.activateKeepAwakeAsync()` na montagem
- 3 colunas `FlatList`: Novos | Em preparo | Prontos
- `usePedidos` (React Query, `refetchInterval: 30000`) + `useSocket` operando em paralelo — socket atualiza `queryClient.setQueryData` diretamente

### PedidoCard

- Header: número do pedido (Manrope 800 22px), mesa/balcão, horário, `Cronometro`
- `Cronometro`: cor verde → âmbar (>80% tempo médio) → vermelho + `Animated.loop` piscante
- Corpo: itens com strikethrough ao marcar, observações em `#FFF3B0`
- Rodapé (minHeight 44px): botões por coluna — Novos: [Iniciar preparo], Em preparo: [Voltar] + [Marcar como pronto], Prontos: [Voltar] + [Finalizar]
- Animações: card novo = slide-in + `Vibration.vibrate(200)`, mover = `Animated.timing`, finalizar = fade-out + scale down

### Resiliência offline

- `useOfflineQueue`: AsyncStorage `'restroOS:offline-queue'`, `addToQueue` + `flushQueue` (PATCH por item, remove os bem-sucedidos)
- `OfflineBanner`: banner amarelo (offline) → banner verde 3s (reconectado) → `flushQueue()`
- Pedidos já carregados preservados na desconexão

### Push notifications

- `push.service.ts`: `requestPermissionsAsync()` + `getExpoPushTokenAsync()` → POST `/api/kds/register-push-token`
- Servidor emite para Expo Push API ao finalizar pedido no PDV
- Toque na notificação: `router.push('/kds?pedidoId=X')`

- Tempo médio de alerta por prato (override local no AsyncStorage)
- Toggle "manter tela ligada" (`expo-keep-awake`)
- Slider volume 0–100% (`expo-av`)
- Toggle tablet/celular (2 colunas em celular)
- Versão (`expo-constants`), tenant conectado

## 5. Módulo 13 — Dashboard Principal Expandido

### Schema Prisma

```prisma
model DashboardSnapshot {
  id                   String   @id @default(cuid())
  tenantId             String
  data                 DateTime
  totalVendas          Decimal
  totalPedidos         Int
  ticketMedio          Decimal
  cmvTotal             Decimal
  cmvPercentual        Decimal
  produtoMaisVendidoId String?
  createdAt            DateTime @default(now())
  tenant               Tenant   @relation(fields: [tenantId], references: [id])
  @@unique([tenantId, data])
  @@index([tenantId, data])
}
```

Job BullMQ cron `'50 23 * * *'`: agrega vendas/pedidos/CMV do dia e faz `upsert` do snapshot. Os snapshots são reutilizados pelo `FinanceiroAlertWorker` (Módulo 11) para detectar CMV elevado por 3 dias consecutivos.

### API Routes

| Rota | Detalhe |
|---|---|
| `GET /api/dashboard/kpis` | `?tenantId&data` — agrega pedidos do dia em tempo real |
| `GET /api/dashboard/grafico` | `?tenantId&data` — por hora: dia atual (live) + semana passada (snapshot) |
| `GET /api/dashboard/heatmap` | `?tenantId&dias=30` — agrega por dia×hora, cache Redis 1h |
| `GET /api/dashboard/estoque-critico` | `?tenantId` — `currentQty = 0` ou `< minimumQty` |
| `GET /api/dashboard/caixa` | `?tenantId&caixaId` — dados simplificados para CAIXA |

### View ADMIN/GERENTE

**1. Saudação + banner de alertas**
- Saudação calculada client-side por `new Date().getHours()`
- Banner vermelho se `AlertsProvider` tiver alertas CRITICA/ALTA — sem fetch extra

**2. Grid de 7 KPI cards**
- Carregados server-side na montagem
- Atualizados via `socket.on('dashboard:atualizar', delta)` — merge com `immer`, sem re-render total
- Cards: Vendas do dia, Pedidos finalizados, Pedidos em aberto (badge pulsante), Ticket médio, CMV do dia (badge verde/vermelho), Produto mais vendido, Operador com mais pedidos

**3. Gráfico de linha (recharts `LineChart`)**
- Estado gerenciado com `zustand` para append eficiente de pontos via socket
- Linha verde: vendas acumuladas do dia (atualiza via socket)
- Linha cinza tracejada: mesmo dia semana passada (estático, carregado na montagem)
- Tooltip: hora + valor atual + valor semana passada

**4. Heatmap semanal (7 × 18)**
- CSS Grid puro — 7 colunas (Dom–Sáb) × 18 linhas (6h–23h)
- `backgroundColor` calculado em JS: `hsl(142, 70%, ${100 - intensity * 60}%)`
- Tooltip via shadcn `Tooltip` ao hover
- React Query `staleTime: 3_600_000`

**5. Top 3 alertas críticos**
- Consome `AlertsProvider` (já no contexto) — zero fetch extra
- Ordena por severidade → `criadoEm`
- Link "Ver todos os alertas →" para `/alertas`

**6. Resumo de estoque crítico**
- React Query `staleTime: 300_000`
- Botão "Lançar entrada" → `/estoque/insumos?id=X`
- Se nenhum crítico: banner verde "Estoque normalizado ✓"

### View CAIXA

Detectada via `useSession()` no client. Renderiza `DashboardCaixa`:
- Pedidos em aberto do operador
- Total vendido na sessão atual
- Ticket médio da sessão
- Últimos 5 pedidos finalizados (número, mesa, total, horário)
- Botão destacado "Abrir PDV →"

### Eventos Socket.IO

| Quando | Evento | Emitido por |
|---|---|---|
| Pedido FINALIZADO | `dashboard:atualizar` com delta de KPIs | `PATCH /api/pedidos/[id]/finalizar` |
| Novo Alert criado | `alerta:novo` | Jobs BullMQ (Módulo 11) |
| Quantidade de insumo alterada | `dashboard:atualizar` com flag `estoqueAtualizado` | `PATCH /api/ingredients/[id]` |
