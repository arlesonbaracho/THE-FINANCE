# Spec: Upgrade Next.js 14 → 15 (+ React 19)

**Data:** 2026-06-22
**Status:** Aprovado (via brainstorming)

---

## Contexto

O `npm audit` (sub-projeto G1) deixou várias vulnerabilidades **high** residuais no `next@14` (14 CVEs) que só têm fix com upgrade major (Next 15). Este sub-projeto faz o upgrade, tratando os breaking changes — com **muita atenção pra não introduzir bugs**.

Superfície medida no codebase:
- **50 arquivos** usam `params: { ... }` (39 rotas dinâmicas). No Next 15 `params`/`searchParams` viram `Promise` (precisam `await`).
- **`cookies()`** em `src/lib/admin-auth.ts` (~7 chamadas) + `src/app/(admin)/layout.tsx` → assíncrono.
- React 18 → **19** (Next 15 exige). `next-auth@4.24.x` (manter v4).

## Decisões (confirmadas)

- **Abordagem:** codemod oficial + ajustes manuais (não manual puro).
- **Execução:** **inline** (mudança acoplada, não tarefas independentes); branch isolada `feat/next-15`.
- **next-auth:** manter v4 (não migrar p/ v5).
- **Rollback:** se algo intransponível (ex.: lib sem compat React 19) ou `next build`/testes não fecharem → descartar a branch; `main` intacta.

## Estratégia (fases com checkpoint)

### Fase 0 — Pré
Registrar `npm audit` (high do next) antes. Confirmar baseline verde (tsc + 431 testes) na branch.

### Fase 1 — Bump + codemods
- `npx @next/codemod@latest upgrade latest` (sobe next/react/react-dom + roda codemods aplicáveis). Se interativo/travar, fallback: editar `package.json` (`next@15`, `react@19`, `react-dom@19`, `eslint-config-next@15`) + `npm install`.
- `npx @next/codemod@latest next-async-request-api .` (converte `params`/`searchParams`/`cookies()`/`headers()` p/ async nos arquivos).
- `git diff --stat` pra ver o alcance.

### Fase 2 — Ajustes manuais (o que o codemod não pega)
- `params` desestruturado em assinaturas que o codemod não reconhece (client components com `use()`, route handlers com tipos custom).
- `cookies()` síncrono em `admin-auth.ts` (funções helper) → `await cookies()` + tornar as funções async + `await` nos chamadores.
- Peer-deps React 19: `npm install` e tratar libs que reclamarem (bumpar as com release compatível; documentar as sem).
- next-auth: se erro de build/peer, bumpar p/ a 4.24.x mais recente.
- Caching: revisar rotas que dependiam de cache default (a maioria é dinâmica/`getSession` → baixo impacto).

### Fase 3 — Verificação (gates obrigatórios)
- `npx tsc --noEmit` limpo (pega a maioria dos erros de async params).
- `npx vitest run` → 431 verdes (ajustar testes que tipam `params` se preciso).
- **`npx next build`** passa (pega erros de página/build que o tsc não vê) — **gate decisivo**.
- `npx next lint` sem novos erros.
- `npm audit` depois: confirmar que as **high do next** sumiram; documentar residual.

### Fase 4 — Smoke test do usuário
Como **não há E2E de navegador** aqui, o usuário roda `npm run dev` e valida fluxos críticos (login, caixa, dashboard, uma rota dinâmica `[slug]`/`[id]`). Só então finishing-a-development-branch.

## Critérios de aceite
- [ ] `next@15` + `react@19` instalados; `params`/`cookies()` async convertidos e corretos.
- [ ] `tsc` / `vitest`(431) / **`next build`** / `lint` verdes.
- [ ] `npm audit` sem as *high* do next; residual documentado.
- [ ] Smoke test do usuário ok.

## Riscos & mitigação
- **Async params em client components** (`'use client'` + `params`): no Next 15 usa-se `React.use(params)`. O codemod trata a maioria; revisar manualmente os client pages com `params` (ex.: `[slug]/caixa`, `[slug]/cozinha`, `[slug]/garcom`, `convite/[token]`).
- **Lib sem compat React 19:** se bloquear, parar e documentar (decisão do usuário: forçar com overrides ou abortar).
- **next build falha em runtime-only:** abortar a branch, sem custo na main.

## Fora de escopo
next-auth v5. Features novas do Next 15 (PPR, after, etc.). Refatorar caching além do necessário. Pushar.
